Overview

The goal was to build a CNN-based classifier for tomato leaf diseases across 11 classes. The dataset (PlantVillage) contains ~23,000 labeled images covering common conditions.

Beyond getting a model to work, the point was to understand the full pipeline: training from scratch vs. transfer learning, how much architecture choice actually matters, and what it takes to get inference running outside a notebook through a simple web interface.

Dataset

PlantVillage

PlantVillage is an open dataset of labeled plant disease images, maintained as a research resource for crop disease detection. The version used here contains tomato leaf images across 11 disease categories, split into train, validation, and test sets.

Model Comparison

From baselines to transfer learning

Four models were trained and evaluated on the same dataset. The first two — a linear classifier and an MLP — were intentional baselines: simple architectures that don't have the inductive biases needed for image data. They performed poorly, as expected. The more important question was how much transfer learning would help over training a CNN from scratch on a relatively small dataset.

Pipeline

Train → Save → Serve

The web interface lets a user select which saved model to use, upload a leaf image, and get a predicted disease class back. All four trained models are available as selectable options. The interface was kept intentionally simple — the goal was to make inference accessible, not to build a production app.

01
Data Loading & Preprocessing
PlantVillage images resized to 224×224, normalized using ImageNet statistics for pretrained models. DataLoaders set up for train, validation, and test splits.
02
Model Training
Four architectures trained: Linear, MLP (from scratch), AlexNet and ResNet-18 (fine-tuned from ImageNet weights). SGD optimizer with momentum and weight decay. Cross-entropy loss.
03
Model Saving
Each trained model saved as a .pth file with weights and class names bundled together for portability.
04
Flask Web Interface
A simple Flask app loads the selected model on request. User uploads an image, the backend runs inference, and returns the predicted class. No notebook, no manual tensor manipulation — just an image in, a label out.
What I took from this
→ Transfer learning is not just faster — the gap in accuracy between the pretrained models (~95–96%) and the from-scratch baselines (~12–43%) made it obvious why it's the default starting point for most real CV work.
→ Getting a model out of a notebook and into a working interface required thinking about things training doesn't surface: loading weights correctly, handling image preprocessing at inference time, and making the whole thing stable enough to not crash on bad input.
→ The MLP failing completely (stuck at ~12% after 10 epochs) wasn't surprising, but watching it happen concretely made the case for convolutional structure more visceral than reading about it.
→ Running into a corrupted image in the validation set that crashed DataLoader at 2am was a good reminder that real data pipelines need handling for edge cases that clean benchmark descriptions don't mention.
